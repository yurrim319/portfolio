# 회고 프로파일링 가이드 (Retrospective Profiling)

> 개발 당시 성능 수치를 따로 기록해두지 않은 기능에 대해, 지금이라도 언리얼 엔진에서 Before/After 수치를 측정해 포트폴리오용 정량 지표로 만드는 방법.

---

## 기본 원칙: A/B 재현

측정 없이 넘어간 기능은 "지금 구조"만 갖고 있고 "예전 구조"는 이미 사라진 경우가 많다. 그래서 재현이 핵심이다.

1. **After(현재 구조)**: 있는 그대로 프로파일링
2. **Before(예전 구조)**: 별도 브랜치나 테스트 레벨에서 예전 방식을 임시로 재현
   - 예: MPC 대신 배경마다 Dynamic Material Instance를 개별 생성
   - 예: Blueprint Interface 없이 에셋마다 C++ 코드를 개별 작성한 것처럼 재현
3. **같은 조건에서 비교**: 같은 씬, 같은 카메라 앵글, 같은 하드웨어, 같은 해상도로 측정해야 숫자가 의미 있음

조건을 완전히 똑같이 맞추기 어렵다면 "근사치"라고 명시하고 쓰는 것도 괜찮다. 없는 것보다 낫다.

---

## 언리얼 엔진 측정 도구

### 1. `stat unit` — 전체 프레임 타임
콘솔(`~` 키)에 입력:
```
stat unit
```
- Frame / Game / Draw / GPU (ms) 4개 항목이 표시됨
- 안정 상태에서 5~10초 지켜보며 평균값을 기록 (한 프레임만 보면 노이즈가 큼)
- 용도: 전체적인 성능 변화(예: PostProcess 뷰 최적화 전후) 측정에 적합

### 2. `stat gpu` — GPU 항목별 비용
```
stat gpu
```
- PostProcess, Lighting, Translucency, Shadow 등 항목별 GPU 비용(ms)을 분리해서 보여줌
- 용도: "PostProcess 최적화로 GPU 비용이 얼마나 줄었는지" 같은 항목 단위 비교에 적합

### 3. `stat scenerendering` — 드로우콜/프리미티브 수
```
stat scenerendering
```
- Draw Calls, Primitives 등 렌더링 부하 지표 확인
- 용도: MPC vs Dynamic Material Instance처럼 "인스턴스/드로우콜 개수" 비교에 적합

### 4. `memreport` / `stat memory` — 메모리 사용량
```
memreport -full
```
- 실행 시 프로젝트의 `Saved/Profiling` 폴더에 상세 메모리 리포트(.memreport)가 생성됨
- 텍스트 파일이라 머티리얼 인스턴스 수, 텍스처 메모리 등을 grep으로 바로 비교 가능
- 용도: "인스턴스 통합으로 메모리 절감"을 수치로 보여줄 때 적합

### 5. Unreal Insights — 정밀 타임라인 분석
- 더 세밀하게 "어떤 함수/틱이 비용을 먹는지"까지 봐야 할 때 사용
- Session Frontend(Window > Developer Tools > Session Frontend) → Insights 탭에서 트레이스 캡처
- CPU/GPU 스레드별 타임라인, 특정 Tick/함수 단위 비용까지 드릴다운 가능
- 진입장벽이 있는 도구라 위 1~4번으로 충분하면 안 써도 됨

---

## 측정 절차 체크리스트

1. 테스트 레벨/씬을 고정한다 (같은 배경, 같은 카메라 위치)
2. 측정 전 몇 초간 안정화 시간을 둔다 (로딩 직후 스파이크 제외)
3. Before/After 각각 3회 이상 측정해 평균을 낸다
4. 콘솔 화면을 스크린샷으로 남겨둔다 (포트폴리오 첨부 자료로도 활용 가능)

---

## 숫자를 포트폴리오 문장으로 바꾸는 법

측정값을 그대로 나열하지 말고 "Before → After (변화율)" 형태로 정리한다.

- "GPU 프레임 타임 X.Xms → Y.Yms (약 Z% 감소)"
- "머티리얼 인스턴스 N개 → M개로 통합"
- "드로우콜 N회 → M회로 감소"
- "메모리 사용량 N MB → M MB"

---

## 재현이 애매하거나 불가능할 때

정확한 재현이 어렵거나 예전 구조를 되살리는 비용이 너무 크다면, 무리하게 숫자를 만들지 않는다.

- 대신 **구조적 축소**로 표현: "배경마다 개별 인스턴스 관리 → 전역 파라미터 1개로 통합"
- 또는 **절차 단계 수**로 표현: "수작업 8단계 → 1단계"
- 숫자를 지어내는 것보다, 근거 있는 정성적 서술이 면접에서 훨씬 신뢰를 준다
