## 개요 (Overview)

 시퀀스 관리용 인하우스툴 3종 제작
 - **Sequencer Create Tool** : Python Script 기반 시퀀스 자동생성 Editor Utility Widget
 - **Mv Seq Track Tool** : c++ 기반 시퀀스 자동 복사, 정리용 Editor Utility Widget
 - **Preview Takes Editor** : c++과 slate widget을 이용한 시네마틱용 모션캡처 데이터 정리 툴

---

## 문제 정의 (Problem)

  기존 시퀀스 제작의 파이프 라인은 신규 시퀀스를 만들때마다 템플릿을 복사해 폴더 경로과 시퀀스 이름을 수작업으로 붙여넣는 방식이었다.
 네이밍·폴더링 규칙을 사람이 직접 맞추다 보니 휴먼에러가 잦았고, 일반적인 세팅에도 30분 - 한시간 이상이 걸렸다.
 
   뮤직비디오, 시네마틱 같은 특수한 상황에는 해당 템플릿으로 대응할 수 없었고 각 컨텐츠마다 일일히 복사하고 리네이밍하고 검수하는 작업을 해야했다.
  복잡한 모캡 데이터 또한 파이프라인 구조를 알고있는 소수의 담당자가 일일히 수작업으로 정리해야했는데 
  생산성이 크게 떨어지고 각 담당자마다 정리 구조가 달라서 이후 파이프라인 통일 시 어려움이 있었다.

---

## 리서치 (Research)

  Python script를 이용해 언리얼 자동화, 파이프라인화 하는것에 관심을 가졌고
 초기엔 **Editor Utility Widget을 통한 editor ui** 개발을 진행했다.(Sequencer Create Tool)
 블루프린트를 이용해 Widget을 제작할 수 있어 러닝커브가 적었고 일일히 에디터 빌드를 배포하지 않아도 된다는 점에서 채택했다.
 
 기존 회사의 파이프라인 툴은 Pyqt로 작업되었지만 해당 방식은 c++ 사용에 제한적이었고 Nas 서버에 위치, 
 Startup script로 부르고 있어 에디터 실행 시 약간의 딜레이 후 사용할 수 있었다. 
 시퀀스 작업은 관련된 팀만 진행하는 일이었기 때문에 Startup script에 전역적으로 추가하는 방식은 맞지 않다고 생각했다.
 또한 에디터 실행 시 스크립트 경로를 찾기위해 딜레이가 생기는 것이 효율적이지 못하고, 프로젝트 별로 툴을 관리하고 싶었다.
 
 따라서 **c++를 이용하여 에디터 확장, 플러그인으로 배포**하는 방식을 택했다. (Mv Seq Track Tool, Preview Takes Editor)

## 구현 (Implementation)

#### 파트 1.  Sequencer Create Tool

**문제 상황** : 신규 시퀀스를 만들 때마다 기존 템플릿을 복사해 폴더 경로와 시퀀스 이름을 수작업으로 붙여넣어야 했고, 팀 간 작업 충돌을 막기 위한 서브시퀀스도 매번 손으로 만들어야 했다. 네이밍·폴더링 규칙을 사람이 직접 맞추다 보니 휴먼에러가 잦았고, 세팅에만 30분 - 한시간 이상이 걸렸다.

**해결** : Blueprint Widget과 Python으로 생성 툴을 제작해, 프로젝트명·콘텐츠 타입·콘텐츠 코드네임(PD팀 제공)·업로드 날짜를 조합해 폴더 경로와 시퀀스 네이밍을 자동 생성하도록 했다. 
팀 간 충돌 방지용 서브시퀀스를 생성 시점에 선택적으로 함께 만들 수 있게 했고, 카메라 프리셋(비율, FOV 등)과 Frame Range/FPS도 함께 설정할 수 있게 했다.

**결과** : 네이밍·폴더 프리셋 오류로 인한 휴먼에러를 약 80% 줄였고, 세팅 작업 시간을 30분 이상에서 약 5분으로 단축했다. 파이프라인에 정식 도입되어 현재까지 사용 중이다.

#### 파트 2.  Mv Seq Track Tool

**문제 상황** : 뮤직비디오처럼 메인 시퀀서의 트랙 단위로 서브시퀀스를 나눠야 하는 프로젝트에서는, 모캡 데이터를 컷 수만큼 일일이 복사하고 컷 넘버를 붙여 리네이밍하는 작업에 매번 2~3시간이 걸렸고 휴먼에러도 잦았다.

**해결** : Data Asset으로 프로젝트 경로를 지정하고 씬 넘버와 모캡 데이터를 입력하면, 필요한 서브시퀀스 수만큼 자동으로 복사·리네이밍하고 팀별로 필요한 데이터만 남기도록 정리하는 툴을 제작했다. 폴더별 컬러링 기능도 추가해 작업자 편의성을 높였다.

**결과** : 2~3시간 걸리던 작업을 1시간 내외로 단축했고 휴먼에러도 크게 줄였다. 파이프라인에 정식 안착해 사용 중이다.


#### 파트 3. Preview Takes Editor

**문제 상황** : 시네마틱 작업 시 모캡 데이터 양이 방대해 애니메이션팀이 프리비즈용으로 필요한 데이터만 손으로 추리기엔 시간이 부족했다. 프리비즈 단계에서도 모캡 데이터 전체와 프리비즈 전용 레퍼런스 클래스·라이팅 데이터가 뒤섞여 있어 구조가 복잡했다.

**해결** : C++로 위젯 컴포넌트를 제작해 에디터에 바인딩하고, 모캡 데이터를 타입(스켈레탈 메시 등 애니메이션 데이터, 라이팅 데이터, 카메라 등)별로 캐스팅해 각 팀이 필요한 데이터만 정리해 서브시퀀스에 담을 수 있도록 했다. Mv Seq Track Tool에서 만든 서브시퀀스 리네이밍·복사·컬러링 함수를 재사용해 팀 규격에 맞춰 일관되게 처리했다.

**결과** : 약 200 - 300컷 규모의 시네마틱 작업에 활용됐으며, 애니메이션팀의 프리비즈 준비 시간을 크게 단축해 프로젝트 진행에 필수적인 툴로 자리잡았다.

## 회고 (Reflection)

 특히 c++의 경우 cast 형 변환, pointer 등 당시엔 구조를 깊게 알지못하고 그저 컴파일 에러를 피하기 위해 사용했던 것들이
 이후 c++ 클라이언트 개발을 위한 지식의 토대가 되어 구조를 이해하고 습득하는데 큰 도움이 되었다.
